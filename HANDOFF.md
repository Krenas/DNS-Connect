## Обновление из приложения
Код updater: app/src/main/java/ru/krenas/dnsanalytics/GitHubUpdateManager.java.
Манифест: https://raw.githubusercontent.com/Krenas/DNS-Connect/main/latest.json.
Приложение проверяет URL, semantic version, размер, SHA-256, пакет и сертификат, загружает APK и вызывает системный Android Installer. Android требует подтверждения пользователя. После публикации Release 2.3.0 манифест должен ссылаться на точный asset DNS-Connect-2.3.0-release.apk.

## Первая установка / подпись
2.1.0 подписан иным сертификатом. Переход с 2.1.0 на 2.3.0 требует резервной копии, удаления 2.1.0, установки 2.3.0 и восстановления backup. Будущие версии должны использовать прежний ключ 2.2.x+, не создавать новый. Ключ хранится только в приватном репозитории Krenas/DNS-Analytics/signing. Его нельзя помещать в публичный репозиторий, source ZIP или GitHub Release.

## Как продолжать в новом чате без загрузки файлов пользователем
1. Создать новый чат **внутри того же ChatGPT Project «DNS»**. Не создавать отдельный чат вне проекта: Project Files уже содержат пользовательские исходники и EXE, они доступны чатам этого проекта.
2. Не просить повторно загружать файлы. Найти через Project Files по именам `2.1.0.zip`, `Download Zip.zip`, `HB_AI_Xbox_DNS.exe`, а также искать `DNS-Connect-2.3.0-source.zip` и `DNS-Connect-2.3.0-release.apk` среди файлов предыдущих сообщений проекта, если они доступны.
3. Открыть этот HANDOFF, README и latest.json. Проверить фактический Release, manifest и наличие `app/build.gradle.kts` в `main`.
4. **До первичной публикации 2.3.0 main не является исходным Android-проектом:** при последней проверке `main/app/build.gradle.kts` отсутствовал, latest.json указывал на 2.1.0, Release v2.3.0 отсутствовал. Не заявлять, что источник уже импортирован.
5. Если 2.3.0 source ZIP найден через Project Files предыдущих сообщений, использовать его как готовый snapshot. Если не найден — использовать уже имеющийся Project File как исходную базу и восстановить изменения, перечисленные в разделе «Что сделано в 2.3.0». Не просить пользователя пересылать ZIP.
6. Если нужен keystore, получить его из закрытого репозитория `Krenas/DNS-Analytics/signing/` только если текущая GitHub-связь имеет доступ; не выводить пароль и не копировать ключ в публичный репозиторий.
7. Изменения собирать с сохранённым ключом, запускать `build-local.sh` и `package-release.sh`. Публиковать APK/source ZIP/SHA256SUMS в Release; обновлять latest.json только после проверки Release assets.
8. Проверять публичный manifest и Release URLs. Реальное тестирование на телефоне отмечать PASS только после фактической проверки. Пользователь не должен вручную загружать файлы в новый чат.

## Не закрывать без проверки
Не заявлять, что релиз опубликован или updater активен, пока GitHub Release действительно не содержит APK, source и SHA256SUMS, main содержит Android source, а публичный latest.json указывает на актуальный APK.


## Работа в новом чате без повторной загрузки файлов
- Создавать новый чат **внутри существующего проекта ChatGPT DNS**, а не отдельный чат вне проекта. Проектные файлы сохраняются между его чатами.
- Не просить пользователя повторно прикреплять исходники и EXE. Они уже находятся среди файлов проекта: `2.1.0.zip`, `Download Zip.zip`, `HB_AI_Xbox_DNS.exe`. Новый чат должен найти их через Project Files (поиск по имени), прочитать/материализовать только то, что нужно.
- Сразу начать с этого HANDOFF и публичного репозитория. Проверить GitHub и latest.json, затем взять проектную базу из прикреплённых Project Files, если исходники ещё не появились в `main`.
- Кандидат 2.3.0 из предыдущего чата пока не загружен в GitHub Release и source ZIP пока не импортирован в `main`. Не утверждать, что он доступен из GitHub. Сначала синхронизировать исходники/релиз и лишь затем считать GitHub единственным source of truth.
- Если пользователь создаёт обычный новый чат вне проекта DNS, проектные вложения не гарантированы; поэтому новый чат следует создавать именно в этом проекте. Пользователь не должен загружать файлы вручную.
