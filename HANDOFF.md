## Первая установка и подпись
- Проверенный 2.1.0 подписан другим сертификатом. Установка 2.2.0 поверх 2.1.0 не сработает.
- Перед переходом: экспортировать резервную копию в приложении, удалить 2.1.0, установить 2.2.0, восстановить данные.
- Все версии 2.2.x и последующие должны подписываться сохранённым ключом из приватного репозитория. Нельзя создавать новый ключ для очередного релиза.
- Android Installer потребует подтверждение установки пользователем; стороннее приложение не может выполнить тихую установку без системного/управляемого доступа.

## Встроенный updater
- Код: `app/src/main/java/ru/krenas/dnsanalytics/GitHubUpdateManager.java`.
- Манифест: `https://raw.githubusercontent.com/Krenas/DNS-Connect/main/latest.json`.
- Клиент проверяет version/URL, размер, SHA-256, package/signing identity и передаёт APK системному установщику.
- Когда 2.2.0 будет опубликован и `latest.json` обновится, пользователь сможет проверить обновление в приложении и подтвердить установку Android.

## Первичная публикация — незавершённый пункт
В публичном репозитории добавлен workflow:
`.github/workflows/publish-uploaded-release.yml`

Он ожидает временную ветку `apk-upload/v2.2.0` с:
- `incoming/release.json`
- `incoming/apk/NNN.b64` — последовательные части Base64 APK
- `incoming/source/NNN.b64` — последовательные части Base64 source ZIP

Workflow сам восстанавливает бинарные файлы, сверяет size/SHA-256, package/version/versionCode, сертификат и source archive, импортирует исходники в `main`, создаёт Release, прикрепляет APK/source/checksums и обновляет `latest.json`. Использовать только точные локально проверенные файлы 2.2.0; не пересобирать APK без нового полного цикла подписи и обновления хешей.

**Проблема:** бинарные файлы ещё не переданы в GitHub. Доступный GitHub-коннектор умеет создавать Git blobs из Base64-текста, но не имеет прямого upload-release-asset действия. В предыдущем чате публикация не была завершена. Нужно либо закончить загрузку частей в указанную ветку через Git Data API, либо использовать разовую ручную загрузку APK и source ZIP в GitHub Release. Для ручного пути после добавления двух ассетов запустить Actions workflow `Bootstrap DNS Connect source` на ветке `main` с input `v2.2.0`: он проверит ассеты, импортирует исходники и обновит `latest.json`. До успешного Release, импорта исходников и проверки публичного `latest.json` задача не закрыта.

1. Прочитать этот файл и текущий `latest.json`.
2. Проверить наличие Release `v2.2.0`, workflow runs и файлов Android-проекта в `main`.
3. Продолжить с публикации уже проверенных файлов, а не начинать проект заново.
