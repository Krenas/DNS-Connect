# DNS Connect

Android-приложение для диагностики DNS-резолверов, интернет-подключения и выбранных сервисов.

- Package: `ru.krenas.dnsanalytics`
- Android 8.0+ (API 26)
- Публичный репозиторий: https://github.com/Krenas/DNS-Connect
- Публичный latest на данный момент: **2.1.0**. Кандидат 2.4.0 собран и проверен, но ещё не опубликован.

## Скачать и обновлять

После публикации 2.4.0 APK и исходники будут доступны в [GitHub Releases](https://github.com/Krenas/DNS-Connect/releases). В 2.4.0 в настройках есть одна кнопка **«Проверить и обновить»**: она проверяет `latest.json`, загружает только более новую версию, сверяет размер/SHA-256/package/version/signature и передаёт APK системному установщику Android. Установку подтверждает пользователь в Android.

Ежедневная автопроверка включается отдельно; она только присылает уведомление и не устанавливает APK автоматически.

## Первая публикация 2.4.0 — одноразовый импорт

Готовый подписанный пакет: `DNS-Connect-2.4.0-release-pack.zip`. Workflow `.github/workflows/publish-release-pack.yml` принимает ZIP напрямую или скачивает его по одноразовой HTTPS-ссылке Dropbox из `incoming/drop/release-pack-url.txt`. Пакет проверяется, исходники импортируются в `main`, затем создаётся Release и обновляется `latest.json` только после проверки файлов.

После передачи одноразовой ссылки никаких ручных запусков GitHub Actions и загрузки ZIP в репозиторий не требуется. Временный файл-ссылка автоматически удаляется после обработки.
 
## Автоматическая сборка APK на GitHub

После первичного импорта исходников workflow `.github/workflows/build-release.yml` автоматически запускается при изменениях кода приложения на `main` (app, gradle, tests и параметры сборки). Он сам берёт версию и versionCode из `app/build.gradle.kts`, заметки — из `CHANGELOG.md`, запускает проверки, собирает и подписывает APK, проверяет сертификат и целостность Release assets и только после этого обновляет `latest.json`. Вручную запускать workflow или загружать ZIP с исходниками для каждого следующего выпуска не нужно.

Для постоянной подписи нужен один защищённый GitHub Actions secret: `DNS_CONNECT_SIGNING_BUNDLE` — Base64 ZIP с ключом подписи и паролем. Его нельзя помещать в публичный репозиторий. Секрет пока не настроен; без него автоматическая сборка новых APK остановится на проверке перед сборкой. Это одноразовая настройка в [Settings → Secrets and variables → Actions](https://github.com/Krenas/DNS-Connect/settings/secrets/actions).

Первый импорт текущей версии 2.4.0 — отдельный стартовый шаг: workflow `.github/workflows/publish-release-pack.yml` проверяет готовый подписанный пакет, публикует Release и переносит исходники в `main`. Для этого начального импорта пока требуется один раз добавить release-pack ZIP в `incoming/drop`. Этот шаг не нужен для последующих версий после импорта исходников.
 
## Подпись и совместимость

Для 2.4.0 создан новый ключ, который нужно сохранять для всех следующих релизов. SHA-256 сертификата: `54b847350b8f4166ea3add400330f360cbc53c4b82e53d709d2c9ff084eb21f7`.

Публичная 2.1.0 и прежний неопубликованный кандидат 2.3.0 подписаны другими сертификатами. Переход на 2.4.0 может потребовать однократного удаления старой установки и повторной установки; удаление может стереть локальные данные, поэтому перед ним нужна резервная копия. После установки 2.4.0 будущие версии с тем же ключом смогут обновляться поверх приложения.

## Правила релизов

- Не обновлять `latest.json`, пока Release не создан и SHA-256/размер GitHub assets не проверены.
- Не публиковать JKS, пароль или signing bundle.
- Каждая следующая версия должна повышать `versionCode` и использовать тот же сертификат, что 2.4.0.
