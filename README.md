## Обновления внутри приложения

В версии 2.4.0 есть одна кнопка **«Проверить и обновить»**. Она выполняет всю последовательность:
1. Получает актуальный `latest.json` из публичного репозитория.
2. Проверяет, что версия новее установленной.
3. Загружает APK из GitHub Release.
4. Проверяет размер, SHA-256, package ID, versionCode и сертификат подписи.
5. Передаёт проверенный APK системному установщику Android.

Пользователю остаётся подтвердить установку в Android. При первой установке обновления Android может один раз запросить разрешение «Установка неизвестных приложений» для DNS Connect. Это системная защита; приложение не пытается обходить её.

Фоновая автопроверка включается отдельно в настройках. Она только сообщает о новой версии уведомлением и не устанавливает её автоматически.

### Подпись и совместимость

Для 2.4.0 и всех следующих версий используется сохранённый ключ 2.2.x. Не менять его при последующих сборках. Уже установленная версия 2.3.0 с этим ключом может обновиться на 2.4.0 из приложения.

Публичная 2.1.0 подписана старым сертификатом, закрытый ключ для него не найден. Поэтому для перехода с 2.1.0 нужна однократная переустановка: удалить 2.1.0 и установить APK 2.4.0. Удаление может стереть локальные данные — перед ним сохранить резервную копию. После перехода на 2.4.0 дальнейшие обновления будут устанавливаться поверх приложения.

### Публикация новых версий

Для публикации готового релиза предусмотрен workflow [Publish verified DNS Connect release pack](https://github.com/Krenas/DNS-Connect/actions/workflows/publish-release-pack.yml). Владелец один раз загружает единый release pack в [папку incoming/drop](https://github.com/Krenas/DNS-Connect/upload/main/incoming/drop) и фиксирует изменения. GitHub Actions автоматически проверит APK и исходники, создаст Release, проверит контрольные суммы и только после этого обновит `latest.json`. Приватный ключ и пароль подписи не загружаются.

## Автоматическая сборка из ZIP

Сборка устроена по схеме «архив исходников → папка incoming → GitHub Actions → APK → GitHub Release → latest.json».

1. Поместить архив с чистым Gradle-проектом в `incoming/DNS-Connect-MAJOR.MINOR.PATCH-source.zip`.
2. Commit/push ZIP в `main`. Workflow `.github/workflows/build-from-archive.yml` запустится автоматически.
3. GitHub Actions проверит структуру ZIP и отсутствие ключей подписи, установит Java 17 и Android SDK 35, запустит тесты и соберёт APK.
4. Workflow проверит пакет, версию, сертификат подписи и zipalign; создаст Release, загрузит APK/source ZIP/checksums и сверит размер/SHA-256.
5. После публикации обновится `latest.json`. DNS Connect сможет найти новую версию через кнопку проверки обновлений.
6. После успешной публикации временный ZIP будет удалён из `incoming`.

Ручной запуск тоже доступен в [GitHub Actions](https://github.com/Krenas/DNS-Connect/actions/workflows/build-from-archive.yml).

### Однократная настройка подписи

Для альтернативного облачного сценария сборки из исходного ZIP (старый `build-from-archive.yml`) нужны два защищённых repository secrets. **Для обычной публикации подготовленного 2.4.0 release pack они не нужны** — используйте [однократную загрузку готового комплекта](https://github.com/Krenas/DNS-Connect/blob/main/incoming/drop/README.md): уже подписанный APK проверяется, но приватный ключ не передаётся.

- `ANDROID_KEYSTORE_BASE64` — Base64 сохранённого JKS из приватного репозитория.
- `ANDROID_KEYSTORE_PASSWORD` — пароль JKS.

Alias `dnsconnect` зафиксирован в workflow; для ключа используется тот же пароль, что и для хранилища. Значения нельзя помещать в публичный репозиторий, исходный ZIP, коммиты или логи. Workflow остановится, если один из двух secrets отсутствует или сертификат не совпадает с сохранённым signer.

Пользователю не нужно самостоятельно собирать APK. Для стандартных обновлений используется pre-signed release pack workflow: одноразовая загрузка ZIP, затем автоматические проверки и публикация. Старый cloud build workflow остаётся дополнительным вариантом и требует signing secrets. В текущей среде GitHub-коннектор позволяет менять исходный код и workflow, но не предоставляет операции загрузки бинарных Release assets или записи repository Actions secrets; поэтому публикация текущего локального кандидата ещё не выполнена.

## Продолжение без повторной загрузки файлов

Создавайте новый чат внутри существующего ChatGPT Project DNS. Project Files проекта уже содержат исходную базу 2.1.0.zip, отдельный `DNS-Connect-2.1.0-source.zip`, компоненты Android SDK и `HB_AI_Xbox_DNS.exe`. Новый чат должен прочитать HANDOFF.md и CHECKPOINT.md, затем использовать постоянный патч из `bootstrap/patch-2.3.0/`. Повторно загружать эти файлы не нужно.

## Постоянный патч 2.3.0

Публичный `bootstrap/patch-2.3.0/` содержит 13 проверенных фрагментов, manifest и инструкции. Строгая проверка GitHub Actions сверяет каждый chunk, полный Base64, gzip и unified diff с SHA-256 в manifest.

## Статус публикации

Локально собранная версия **2.4.0 / versionCode 25** содержит объединённое действие проверки и установки обновления. Автоматические проверки: **266 PASS / 0 FAIL**; APK Signature Scheme v2/v3, zipalign, package ID, SHA-256 и проверка сертификата — PASS. Повторная сборка исходников с сохранённым приватным ключом совпала с APK по всем 26 ZIP-записям.

- APK: 1,198,136 bytes; SHA-256: `d8e0e07de730161015cdfa6d9d985ed83619969bb526390c72c8bf85e12b4822`.
- Source ZIP: 995,791 bytes; SHA-256: `2ac314c55f5d553cdb62141d9e41ad109bcdca688b659710ef5ed005e361afd1`.
- Release pack: 1,952,221 bytes; SHA-256: `a2b4e5561e35212ce3a36a8cbac252b11a2a3e216f0143358060a2237f6a430f`.
- Полный QA-отчёт находится в release pack; исходники и упаковщик содержат обновлённый однокнопочный updater.

GitHub Actions workflow публикации release pack проверен отдельными dry-run запусками и actionlint. Текущие сухие прогоны успешно заканчиваются без публикации, когда ZIP не загружен. Сам публичный Release 2.4.0 пока не создан, поэтому `latest.json` корректно остаётся на 2.1.0. Чтобы активировать обновление внутри приложения, нужно один раз загрузить release pack через [форму GitHub](https://github.com/Krenas/DNS-Connect/upload/main/incoming/drop) и нажать Commit changes. После автоматической публикации кнопка в приложении начнёт находить 2.4.0.
