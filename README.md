# DNS Connect

Android-приложение для диагностики DNS, доступности интернет-сервисов и состояния сетевого подключения.

- Android 8.0+ (API 26)
- Package: `ru.krenas.dnsanalytics`
- Текущая опубликованная версия определяется только из [latest.json](https://raw.githubusercontent.com/Krenas/DNS-Connect/main/latest.json).

## Скачать

- [Последний стабильный релиз](https://github.com/Krenas/DNS-Connect/releases/latest)
- [Все версии и архивы исходников](https://github.com/Krenas/DNS-Connect/releases)
- [Текущий APK для встроенного обновления](https://raw.githubusercontent.com/Krenas/DNS-Connect/main/latest.json)

Каждый стабильный релиз должен содержать два обязательных файла:
- `DNS-Connect-VERSION-release.apk`
- `DNS-Connect-VERSION-source.zip`

### Первичная публикация исходников

В репозитории уже настроена автоматизация, но исходный код пока нужно импортировать один раз. Для этого создайте релиз с тегом `v2.2.0`, прикрепите два файла из локального комплекта 2.2.0 — APK и ZIP исходников — и опубликуйте релиз. Workflow `publish-latest-manifest.yml` проверит оба файла, импортирует исходники в `main` и обновит `latest.json`. После успешного запуска новый чат сможет брать код из репозитория и архива релиза без повторной отправки файлов в чат.

Для следующих версий используйте `Build and publish DNS Connect`: сборка запускается из `main`, подписывает APK сохранённым GitHub Actions secret, создаёт ZIP исходников и публикует оба файла в одном релизе.

Архив исходников — точный снимок кода, из которого собран соответствующий APK. GitHub Actions проверяет имя, версию, пакет, сертификат APK, SHA-256, размер и соответствие версии исходного архива. После успешной проверки исходный проект импортируется в `main`, а `latest.json` обновляется автоматически.

## Продолжение разработки в новом чате

Откройте новый чат и передайте только ссылку на этот репозиторий:

`https://github.com/Krenas/DNS-Connect`

Новый чат должен начать с [HANDOFF.md](HANDOFF.md), затем прочитать `latest.json` и взять соответствующий архив исходников из последнего релиза. Не требуется повторно прикреплять APK или исходники к чату.

## Сборка и выпуск

После первичного импорта исходников в `main` следующие версии собираются из репозитория через GitHub Actions:

[Build and publish DNS Connect](https://github.com/Krenas/DNS-Connect/actions/workflows/build-release.yml)

Для подписания релиза нужны зашифрованные Repository Actions secrets:
- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

В репозиторий не загружаются JKS, приватные ключи, пароли или токены. Закрытый ключ хранится только в зашифрованном хранилище GitHub Actions. Ожидаемый SHA-256 сертификата для выпусков 2.2.x: `4dc48085b7ea161b57e6266611c5d6a28514df6f2ddfc26df14f3ac972debf90`.

## Основные возможности

- Проверка DNS-серверов UDP, DoT и DoH.
- Сравнение задержки и диагностика доступности сервисов.
- Каталог DNS-профилей с фильтрами по назначению.
- История результатов, экспорт и восстановление резервной копии.
- Виджеты DNS, скорости, сервисов и быстрых действий.
- Системная плитка Android для запуска диагностики.
- Встроенная проверка обновлений через GitHub-манифест с проверкой SHA-256, пакета и сертификата.

## Важное о переходе 2.1.0 → 2.2.0

Оригинальный закрытый ключ 2.1.0 не был предоставлен. Поэтому 2.2.0 подписывается новым ключом. Android не разрешит установить её поверх 2.1.0: сначала экспортируйте резервную копию, удалите 2.1.0, установите 2.2.0 и восстановите данные. Обновления, подписанные сохранённым ключом 2.2.x, совместимы между собой.

## Ограничения проверки

Успешная автоматическая сборка и проверки не заменяют установку и тестирование на физическом Android-устройстве. До проверки на телефоне соответствующие пункты должны отмечаться как NOT TESTED.
