# DNS Connect

Android-приложение для диагностики DNS-резолверов, интернет-подключения и выбранных сервисов.

- Package: `ru.krenas.dnsanalytics`
- Android 8.0+ (API 26)
- Публичный репозиторий: https://github.com/Krenas/DNS-Connect
- Последний публичный релиз на момент этой записи: **2.1.0**. Версия 2.4.0 собрана и проверена, но ещё не опубликована.

## Обновление внутри приложения

В DNS Connect 2.4.0 в настройках одна кнопка **«Проверить и обновить»**. Она получает `latest.json` из публичного репозитория, проверяет номер версии, скачивает APK только при наличии новой версии, проверяет URL, размер, SHA-256, package ID и подпись, затем передаёт APK системному установщику Android. Установку подтверждает пользователь в Android.

Ежедневная автопроверка включается отдельно. Она только присылает уведомление и не скачивает/не устанавливает APK в фоне.

## GitHub Actions: сборка APK и публикация релиза

Основной путь — GitHub Actions собирает APK из исходного ZIP и публикует его в GitHub Releases.

### Однократная настройка подписи

1. Открой [Settings → Secrets and variables → Actions → New repository secret](https://github.com/Krenas/DNS-Connect/settings/secrets/actions/new).
2. Создай секрет с именем **`DNS_CONNECT_SIGNING_BUNDLE`**.
3. Вставь в значение содержимое отдельного приватного файла `DNS-Connect-2.4.0-GitHub-Signing-Secret.txt`, полученного вместе с релизным комплектом в текущем чате. Файл содержит Base64-представление архива JKS+пароля. Не добавляй его в репозиторий, коммиты, ZIP исходников или публичные Issue.

### Сборка и публикация

1. Открой [загрузку в папку incoming](https://github.com/Krenas/DNS-Connect/upload/main/incoming).
2. Загрузи `DNS-Connect-2.4.0-source.zip` и нажми **Commit changes**.
3. Workflow `.github/workflows/build-from-archive.yml` запустится автоматически: проверит ZIP, выполнит тесты, соберёт APK на Java 17 + Android SDK 35, проверит пакет, версию, подпись и zipalign, загрузит APK/исходники/checksums в GitHub Release, затем обновит `latest.json`.
4. После успешного workflow приложение найдёт 2.4.0 через **«Проверить и обновить»**. Для последующих выпусков используется та же подпись и тот же секрет.

Секрет создаётся один раз. Не меняй ключ подписи в будущих версиях.

### Альтернативный путь без GitHub signing secret

Если не требуется повторная сборка на GitHub, можно загрузить единый заранее подписанный release pack в [incoming/drop](https://github.com/Krenas/DNS-Connect/upload/main/incoming/drop). Workflow `.github/workflows/publish-release-pack.yml` проверит APK и исходники, создаст Release и обновит `latest.json`. Этот резервный сценарий публикует готовый APK, а не пересобирает его.

## Подпись и совместимость

Для 2.4.0 создан новый ключ, который нужно сохранять для всех последующих релизов. SHA-256 сертификата: `54b847350b8f4166ea3add400330f360cbc53c4b82e53d709d2c9ff084eb21f7`.

Публичная 2.1.0 и предыдущий неопубликованный кандидат 2.3.0 подписаны другими сертификатами. Переход на 2.4.0 может потребовать однократного удаления старой установки и повторной установки; удаление может стереть локальные данные, поэтому перед ним нужна резервная копия. После установки 2.4.0 будущие версии с тем же новым ключом смогут обновляться поверх приложения.

## Правила релизов

- Не обновлять `latest.json`, пока GitHub Release не создан и SHA-256/размер загруженных assets не проверены.
- Не публиковать JKS, пароль или signing bundle.
- Каждая новая версия должна повышать `versionCode` и использовать тот же signer, что и 2.4.0.
